## 二、缺陷与修复清单

### 1. 【高】已发布成绩可被「不传版本号」静默覆盖（M2）

- **现象**：对已有成绩的行提交 `expectedVersion: null`，接口返回 `code=0` 并直接改写分数。实测把 A 班**已确认发布**的 88 分改成了 70 分，学生端看到的分数随之变化。
- **根因**：`ScoreServiceImpl.saveScores` 只在 `expectedVersion != null` 时才比对版本；为 null 时跳过比对，而 `@Version` 用的是刚查出来的最新版本，等于永远成功。
- **修复**：`backend/.../score/service/impl/ScoreServiceImpl.java` —— 库中行已存在且 `expectedVersion == null` 时直接抛 3010 并指名到人；新行仍按 null 走插入。
- **验证**：E09（已存在行不传版本 → 3010）、E16（A 班 88 分未被覆盖）、单测 `saveScoresShouldRejectNullExpectedVersionWhenRowExistsWith3010`。

### 2. 【高】「清空成绩」不落库（H2）

- **现象**：录 55 分 → 清空 → 暂存 → 刷新，分数又回来了；接口却回 `saved=1`。
- **根因**：`Score.score` 未声明更新策略，MyBatis-Plus 默认 `NOT_NULL`，null 字段不进 SET 子句，SQL 只更新了 `version`。
- **修复**：`score/entity/Score.java` —— `score` 字段加 `@TableField(updateStrategy = FieldStrategy.ALWAYS)`。
- **验证**：E07/E08（清空后 `score=null`）、E11（清空后可再录入）、单测 `scoreFieldShouldAlwaysBeWrittenSoClearingPersists`。

### 3. 【高】半确认课程可被删除/改名，已公布成绩随之消失（H3）

- **现象**：A 班已确认、B 班草稿（课程状态仍是 DRAFT）时，`DELETE /api/courses/{id}` 返回 `code=0`，课程、成员、成绩被物理删除；`PUT` 改名同样放行。学生端从「已公布」直接变成「没有该课程」。
- **根因**：`CourseServiceImpl.update/delete` 只判 `status == CONFIRMED`，而状态要等**全部分组**确认才升级。
- **修复**：`course/service/impl/CourseServiceImpl.java` —— 新增 `hasConfirmedGroup(courseId)` 与 `requireNotPublished(course)`，任一分组已确认即抛 3003。
- **验证**：H07/H08、单测 `deleteShouldRejectWhenAnyGroupConfirmed` / `updateShouldRejectWhenAnyGroupConfirmed` / `updateShouldWorkWhenNoGroupConfirmed`。

### 4. 【中】已确认分组仍可加入新成员，公布状态回退（M3）

- **现象**：A 班已确认发布后，把 A 班新学生加入课程，该行 `groupConfirmed=false`，整组统计从「已公布」翻回「草稿」；同组其他学生显示已公布、本人显示未公布。
- **根因**：`addMembers` 只拦 `course.status == CONFIRMED`，锁粒度是「课程」而不是「分组」。
- **修复**：`course/service/impl/CourseMemberServiceImpl.java` —— 先收集已确认分组的 `classId`，目标班级分组已确认的学生跳过并计数；`MemberAddResult` 增加 `skippedConfirmed`，接口返回 `{added, skipped, skippedConfirmed}`；前端 `CourseMembers.vue` 提示区分两种跳过原因。
- **验证**：H09（`added=0, skippedConfirmed=1`）、单测 `addMembersShouldSkipStudentOfConfirmedGroupAndReportSkippedConfirmed` / `addMembersShouldStillAcceptStudentOfUnconfirmedGroup`。

### 5. 【中】改学号/姓名不同步登录账号（M4）

- **现象**：把学号从 `...03` 改成 `...99` 后，新学号登录返回 1001，**旧学号仍能登录**；账号显示名也不跟着改。
- **根因**：`StudentServiceImpl.update` 只更新 `student` 表，没有同步 `sys_user.username / display_name`，且方法未加事务。
- **修复**：`student/service/impl/StudentServiceImpl.java` —— `update` 加 `@Transactional`，学号/姓名变更时同步账号；新学号被其他账号占用抛 2005（整体回滚）；绑定指向教师账号时不动它。
- **验证**：H10–H12、单测 `updateShouldSyncAccountUsernameAndDisplayName` / `updateShouldRejectWhenNewStudentNoTakenByAnotherAccountWith2005` / `updateShouldNotTouchTeacherAccountEvenIfBoundByMistake`。

### 6. 【中】整课确认后批量保存成绩整批 3003，与文档口径不一致（H1 遗留）

- **现象**：全部分组确认后再调 `PUT /scores`，返回 3003；`docs/API.md` 写的是「按行跳过，返回 `saved/skipped`」。
- **根因**：`saveScores` 开头有一段「课程 CONFIRMED 就整体抛 3003」的旧逻辑，与后来的分组跳过逻辑重叠。
- **修复**：`ScoreServiceImpl.saveScores` —— 删掉该整体拒绝分支，全部靠行级 `groupConfirmed` 跳过（已确认行不会被写入）。
- **验证**：E19（`code=0, saved=0, skipped=1`）、单测 `saveScoresShouldNeverWriteScoreOfConfirmedGroupEvenAfterCourseConfirmed`。

### 7. 【中】Excel 全部行非法时抛 2006，不返回失败清单（L2）

- **现象**：导入 2 行「学号已存在」的学生文件，返回 2006「文件中没有可导入的数据行」，教师看不到具体原因。
- **根因**：`importExcel` 的 `hasDataRow` 标记放在各项校验之后，全部行被过滤时不置位。
- **修复**：`StudentServiceImpl.importExcel` —— 读到数据行就置位（不论是否合法），只有整表为空/仅表头才抛 2006。
- **验证**：C02（`code=0, successCount=0, failures=2`，行号 2/3）、单测 `importExcelShouldReportFailuresInsteadOfParseErrorWhenEveryRowInvalid` / `importExcelShouldRejectEmptyFileWith2006`。

### 8. 【低】导入缺少 `file` 字段返回 5000（异常兜底不规范）

- **现象**：`POST /classes/{id}/students/import` 不带 form-data 时返回 `5000 系统繁忙`。
- **根因**：Spring 抛 `MultipartException`，`GlobalExceptionHandler` 没有对应分支，落到兜底。
- **修复**：`common/GlobalExceptionHandler.java` —— 新增 `MultipartException`、`MissingServletRequestPartException`、`MissingServletRequestParameterException`、`MethodArgumentTypeMismatchException`、`HttpMessageNotReadableException` 五类处理，统一归 4001 并指明字段。
- **验证**：C04（4001，message「请以 form-data 方式上传文件，字段名为 file」）。

### 9. 【低】教师访问学生自助接口返回空列表而不是 1003

- **现象**：`teacher01` 调 `GET /api/my/scores` 得到 `code=0, data=[]`。
- **根因**：`ScoreController.myScores` 用 `SessionUser.require`（只校验登录），未校验角色。
- **修复**：改用 `SessionUser.requireStudent`；`docs/API.md` 补「仅学生角色可调」。
- **验证**：A09（1003）。

### 10. 【低】统计接口遇到空班级快照会 5000

- **现象**：`course_member.class_id` 为 null 的历史数据会让 `GET /statistics` 抛 NPE。
- **根因**：`Collectors.groupingBy` 的 key 不允许为 null。
- **修复**：`ScoreServiceImpl.statistics` 改为手工 `LinkedHashMap` 分组，null 归入「未分班」组（`classId` 为 null，前端据此禁用该组确认）。
- **验证**：单测 `statisticsShouldTolerateMemberWithoutClassSnapshot`。

### 11. 【低】前端首页 favicon 404

- **现象**：每次打开页面控制台都有一条 `404 Not Found`。
- **修复**：`frontend/index.html` 内联 SVG favicon。
- **验证**：页面冒烟「控制台错误 0 条」。

### 12. 【低】「加入成员」提示把「分组已锁定」误报成「已在课程中」

- **现象**：M3 生效后，被跳过的原因是「分组已确认」，但提示仍写「已在课程中」，教师会以为重复添加。
- **修复**：`CourseMembers.vue` 按 `skipped` / `skippedConfirmed` 分开措辞。
- **验证**：H09 + 前端构建通过。

## 五、如何复跑

```bash
# 0) 依赖（仅首次）
python -m venv <env> && <env>/Scripts/pip install openpyxl requests

# 1) 后端（干净库）
mysql -uroot -p -e "DROP DATABASE IF EXISTS grade_manager;"
cd backend && DB_PASSWORD=你的密码 java -jar target/grade-manager-backend-0.0.1-SNAPSHOT.jar

# 2) 前端
cd frontend && npm run dev

# 3) 三层测试
cd backend && mvn test
python _test/e2e_test.py          # 102 条断言，结果写 _test/e2e_result.json
node _test/ui_smoke.mjs           # 截图写 _test/ui_shots/
```

> 端到端脚本每次用「时分秒」生成班级名与学号，可反复执行且不互相干扰。
> 测试会在库里留下若干「测试A班/测试B班、测试课程一/二」的数据；需要干净环境时执行上面的 `DROP DATABASE` 后重启后端即可。

## 六、遗留观察（不影响验收）

1. MySQL 8 提示 `TINYINT(1)` 显示宽度已废弃（SQL State 1681），属告警，不影响运行；后续新增迁移时可用 `TINYINT` 或 `BOOLEAN`。
2. 学生「首次登录强制改密」会让新建/导入的学生在改密前无法查成绩，测试脚本里必须先改密——演示时建议提前说明，避免误判为「登录后白屏」。
3. `score` 表 `updated_at` 依赖 MySQL 的 `ON UPDATE`，无操作人信息（L6），成绩争议排查仍缺依据。
