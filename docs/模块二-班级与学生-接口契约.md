## 1. 模块范围与职责边界

### 1.1 本模块做什么

对应需求《项目背景与需求说明》§6-2「班级与学生」：

| 需求条目 | 本文档落实为 |
| --- | --- |

| 事项 | 归属 | 说明 |
| --- | --- | --- |

### 1.3 角色与权限边界

| 项 | 约定 |
| --- | --- |
| 本模块**全部接口**仅允许 `role=TEACHER` | 学生调用一律 `1003`，不做任何数据裁剪后放行 |

## 3. 数据模型

### 3.1 实体关系

```
sys_user (已有, V1)
   │  1
   │
   │  1
student ────────── N school_class
   │                     │
   │  class_id (FK)      │  status: 1=正常 0=已归档
   │                     │
   └── status: 1=在读 0=停用
```

- `sys_user` 与 `student` 是 **1:1**：一个学生账号对应一条学生档案，靠 `student.user_id` 唯一索引保证。
- `school_class` 与 `student` 是 **1:N**：一个班级多名学生。
- **姓名只存一处**：`sys_user.display_name`。`student` 表**不冗余** name 字段，查询时 JOIN 取。理由：双写必然产生不一致，而学生列表的查询量不值得用冗余换性能。
- 模块二**不建** `course` / `course_class` / `grade` 表；那些属于模块三、四。

### 3.2 `school_class`（班级，新增）

> 表名用 `school_class` 而非 `class`：`class` 在 Java 是关键字、在 SQL 里也是高危命名，容易在 ORM 映射与手写 SQL 上踩坑。

| 字段 | 类型 | 空 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| id | BIGINT UNSIGNED | 否 | AUTO_INCREMENT | 主键 |
| name | VARCHAR(64) | 否 | — | 班级名称，如「计算机2301班」。**去首尾空格后 1–64 字符** |
| grade_year | SMALLINT | 是 | NULL | 年级，如 `2023`；允许为空。取值范围 2000–2100 |
| status | TINYINT | 否 | 1 | `1`=正常，`0`=已归档（对应"删除"） |
| archived_at | DATETIME | 是 | NULL | 归档时间；`status=0` 时非空 |
| created_by | BIGINT UNSIGNED | 否 | — | 创建者 `sys_user.id`（仅审计，不作权限边界） |
| created_at | DATETIME | 否 | CURRENT_TIMESTAMP | — |
| updated_at | DATETIME | 否 | CURRENT_TIMESTAMP ON UPDATE | — |

索引与约束：

| 名称 | 类型 | 说明 |
| --- | --- | --- |
| `uk_school_class_name` | UNIQUE (`name`, `grade_year`, `status`) | 见下方说明 |
| `idx_school_class_status` | INDEX (`status`) | 列表默认按 `status=1` 过滤 |

> **唯一性的实现口径**：MySQL 不支持"仅对 `status=1` 生效"的部分唯一索引，因此采用「唯一索引 + 服务层优先校验」两层：
> 1. 服务层先查 `status=1` 且同名同年级是否已存在 → 存在即返回 `2001`（message 指明冲突的班级名）；
> 2. 唯一索引做并发兜底，捕获 `DuplicateKeyException` 同样转 `2001`。
> 注意：`uk` 含 `status` 意味着归档后的同名班级不会挡住新建——这正是需求要的（名字错了归档后能重建）。
> **代价必须知道**：同一 `(name, grade_year)` 只能存在**一条** `status=0` 的归档记录，第二次归档同名班级会撞唯一索引。所以归档时若检测到已存在同 `(name, grade_year)` 的归档记录，服务层直接**物理删除旧的那条归档记录**（它已无学生引用才会进入此分支，见 §6.3），再归档当前班级。此逻辑必须在实现时写进注释，否则后人看不懂为什么要删一行。

### 3.3 `student`（学生档案，新增）

| 字段 | 类型 | 空 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| id | BIGINT UNSIGNED | 否 | AUTO_INCREMENT | 主键，即接口里的 `studentId` |
| user_id | BIGINT UNSIGNED | 否 | — | → `sys_user.id`，**唯一** |
| student_no | VARCHAR(32) | 否 | — | 学号，**唯一**。业务标识，可修改 |
| class_id | BIGINT UNSIGNED | 否 | — | → `school_class.id`。**不允许为空**（学生必须有班） |
| status | TINYINT | 否 | 1 | `1`=在读，`0`=停用（停用后不能登录、不能加课） |
| created_at | DATETIME | 否 | CURRENT_TIMESTAMP | — |
| updated_at | DATETIME | 否 | CURRENT_TIMESTAMP ON UPDATE | — |

索引与约束：

| 名称 | 类型 | 说明 |
| --- | --- | --- |
| `uk_student_user_id` | UNIQUE (`user_id`) | 保证 1:1 |
| `uk_student_student_no` | UNIQUE (`student_no`) | 学号唯一 |
| `idx_student_class_id` | INDEX (`class_id`) | 班级名单查询 |
| `fk_student_class` | FOREIGN KEY (`class_id`) → `school_class(id)` | **不加 ON DELETE CASCADE**（见 §6.3） |
| `ck_student_status` | CHECK (`status` IN (0,1)) | — |

### 3.4 学号与登录名的关系（**必须严格遵守**）

| 字段 | 所在表 | 角色 | 能否修改 |
| --- | --- | --- | --- |
| `student_no` | `student` | **业务标识**：名单、成绩单、导出都用它 | ✅ 可修改（转学、录入纠错） |
| `username` | `sys_user` | **认证标识**：学生登录时输入 | ❌ 建号后**永不修改** |

规则：

1. **建号时** `username` 直接取 `student_no`（学生登录输学号最自然）。
2. **改学号时**（S5）只更新 `student.student_no`，`sys_user.username` 保持不变，**且不要求两者再相等**。
3. 因此存在"学号已改、登录名还是旧学号"的合法状态。前端在学生详情里**必须同时展示 `studentNo` 与 `username`**，并给出提示文案「登录名不随学号变更」，否则教师会困惑。
4. `student_no` 与 `username` 各自唯一，**冲突要分别判定**（`2003` 与 `2007`，见 §4）。

### 3.5 账号与档案的一致性

`student` 行与 `sys_user` 行**必须同时存在**。任何一侧缺失都属于脏数据，处理口径：

- 建号 = 同一事务内插两张表，任一失败整体回滚（不做"先建账号再补档案"的两段式）。
- 不做物理删除，所以不存在"删了一边留一边"的正常路径。
- 排障 SQL（写进联调指南，供联调时自查）：

```sql
-- 有账号无档案（应返回空）
SELECT u.id, u.username FROM sys_user u
LEFT JOIN student s ON s.user_id = u.id
WHERE u.role = 'STUDENT' AND s.id IS NULL;

-- 有档案无账号（应返回空）
SELECT s.id, s.student_no FROM student s
LEFT JOIN sys_user u ON u.id = s.user_id
WHERE u.id IS NULL;
```

## 4. 错误码

### 4.1 继承自通用错误码（模块二会用到）

| code | 含义 | 模块二触发场景 |
| --- | --- | --- |
| 0 | 成功 | — |
| 1002 | 未登录/会话过期 | 未登录调用本模块任何接口 → 前端跳登录页 |
| 1003 | 权限不足 | 学生身份调用本模块任何接口 |
| 4001 | 参数校验失败 | 必填缺失、格式非法、类型不匹配、JSON 结构错误。message 必须指出**具体字段** |
| 5000 | 系统内部错误 | 未捕获异常 |

### 4.2 模块二新增（**2xxx 号段**，不得越段使用）

| code | 常量名 | 含义 | 触发场景 | message 示例 |
| --- | --- | --- | --- | --- |
| 2001 | `CLASS_NAME_DUPLICATED` | 班级名称已存在 | 新建/重命名时 `status=1` 下已有同名同年级班级 | `班级「计算机2301班」已存在` |
| 2002 | `CLASS_NOT_FOUND` | 班级不存在或已归档 | 路径里的 `classId` 查无此班，或该班 `status=0` | `班级不存在或已归档` |
| 2003 | `STUDENT_NO_DUPLICATED` | 学号已被占用 | 建号或改学号时 `student.student_no` 冲突 | `学号 2023010101 已被占用` |
| 2004 | `STUDENT_NOT_FOUND` | 学生不存在 | 路径里的 `studentId` 查无此人 | `学生不存在` |
| 2005 | `CLASS_HAS_DRAFT_GRADES` | 班级存在未发布成绩，不可归档 | **模块四启用**，模块二恒不触发 | `该班级已有 12 条成绩录入未发布，请先完成确认或清空后再归档` |
| 2006 | `TARGET_CLASS_ARCHIVED` | 目标班级已归档 | 往已归档班级加学生、或把学生转入已归档班级 | `目标班级已归档，不能接收学生` |
| 2007 | `USERNAME_DUPLICATED` | 登录名已被占用 | 学号与某个**非本学生**的 `sys_user.username` 冲突（例如学号恰好等于某教师登录名） | `登录名 2023010101 已被占用` |

**号段纪律**：`2xxx` 归模块二独占；模块三用 `3xxx`，模块四用 `4xxx`，模块五/六用 `5xxx`/`6xxx`。**已分配的码永不复用**（含删除后留下的空号，参照主契约对 `1004` 的处理）。

### 4.3 异常处理约定

| 场景 | 处理 | 是否记录日志 |
| --- | --- | --- |
| 业务规则不满足（重名、不存在、已归档） | 抛 `BusinessException(code, message)`，由全局处理器包装 | INFO，含业务关键参数，不含口令 |
| `@Valid` 校验失败 | 全局处理器转 `4001`，message 取第一条字段错误 | 不记 |
| JSON 结构错误、类型不匹配、路径参数非数字 | 全局处理器转 `4001`，message 固定「请求参数格式不正确」 | 不记 |
| 数据库唯一索引冲突 | 服务层捕获 `DuplicateKeyException`，按冲突的索引名转 `2001`/`2003`/`2007` | WARN，含索引名 |
| 未预期异常 | `5000`，**日志记完整堆栈，message 不外泄内部细节** | ERROR |
| 初始口令 | **任何日志、任何异常 message 都不出现明文** | — |

**批量操作的失败语义**：除扩展接口 **B1（批量导入学生）** 外，本模块无批量接口，均为全成功或全失败。**B1 采用部分成功语义**：逐行独立事务，成功行提交、失败行返回行号与原因（详见 §5-B1）。

### C1 · GET `/api/classes` —— 班级列表

**用途**：教师端班级列表页，按名称/年级检索，默认只返回未归档班级。

**职责边界**
- ✅ 只返回班级本身的信息与当前学生数。
- ❌ 不做成绩相关统计（未录入数、不及格数属于模块四/六）。
- ❌ 不返回已归档班级，除非显式传 `status=0`。

**权限**：`TEACHER`

**查询参数**

| 参数 | 位置 | 类型 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- | --- | --- |
| keyword | query | string | 否 | — | 对 `name` 模糊匹配，最长 64；空串等同于不传 |
| gradeYear | query | number | 否 | — | 精确匹配年级 |
| status | query | number | 否 | 1 | `1`=只看正常；`0`=只看已归档；**不传按 1 处理** |
| page | query | number | 否 | 1 | ≥1 |
| size | query | number | 否 | 10 | 1–100 |

**成功响应**

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "list": [
      {
        "classId": 3,
        "className": "计算机2301班",
        "gradeYear": 2023,
        "studentCount": 42,
        "status": 1,
        "archivedAt": null,
        "createdAt": "2026-11-03 20:11:02"
      }
    ],
    "total": 1,
    "page": 1,
    "size": 10
  }
}
```

**data.list[] 字段**

| 字段 | 类型 | 说明 |
| --- | --- | --- |

### C4 · DELETE `/api/classes/{classId}` —— 归档班级（"删除"）

**用途**：班级建错或已结课，从教师端列表移除。

**职责边界**
- ✅ **软删除**：置 `status=0` + `archived_at=now`。班级行保留，学生行保留，`student.class_id` 指向不变。
- ❌ **绝不做物理 DELETE**，也不做级联删除学生。需求 §6-2a 明确要求"删除时不破坏已有的学生与成绩数据"。
- ❌ 不删学生账号，不删学生档案，不删任何成绩。
- ❌ 模块二阶段**不校验成绩**（成绩表还不存在）；校验位见 §6.3。

**权限**：`TEACHER`

**路径参数**：`classId`（number，必填）

**成功响应**

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "classId": 3,
    "className": "计算机2301班",
    "archivedAt": "2026-11-03 22:35:10",
    "affectedStudentCount": 42
  }
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| affectedStudentCount | number | 该班当时的学生数。**前端二次确认必须展示这个数字**，让教师知道自己在归档什么 |

**失败**

| code | 条件 |
| --- | --- |
| 2002 | `classId` 不存在或**已归档**（重复归档返回 2002，不幂等成功） |
| 2005 | 存在未发布成绩（模块四启用后）；message 必须带上学生姓名或条数 |
| 4001 | `classId` 非数字 |

**幂等性**：**不幂等**。第二次调用返回 `2002`。理由：归档是有后果的操作，静默成功会掩盖"前端误发了两次"这种 bug。

**归档后的连锁效果（必须全部实现，缺一条就是 bug）**

| 影响面 | 行为 |
| --- | --- |
| C1 列表 | 默认 `status=1` 过滤后不再出现；显式 `status=0` 可查 |
| C3 改名 | 拒绝，`2002` |
| S1 名单 | **仍可查**（`GET` 允许查看历史班级名单），但响应里 `className` 后缀或 `classStatus=0` 需让前端能显示「已归档」 |
| S2 加学生 | 拒绝，`2006` |
| 学生详情/查询 | 学生仍存在，`className` 仍能显示，前端标注「已归档」 |
| 学生登录 | **不受影响**，学生照常登录 |
| 模块四的成绩查询 | 学生仍能查到该班的历史成绩（前提是成绩行不动） |

### S2 · POST `/api/classes/{classId}/students` —— 添加学生（建号）

> **本模块最关键的接口**。一次请求同时创建账号与档案，并返回**只出现一次**的初始口令。

**用途**：教师给班级添加学生，系统同步开通该学生的登录账号。

**职责边界**
- ✅ 同一事务内写 `sys_user` + `student`。
- ✅ 服务端**生成**初始口令，BCrypt 入库，明文只在响应里返回一次。
- ❌ 请求体中**不接收 password**（客户端提供的口令不可信，且会造成"教师设弱口令"）。
- ❌ 单条接口不做批量导入，一次一个（批量导入由扩展接口 B1 承担）。
- ❌ 不自动登录该学生（服务端不碰请求方会话）。
- ❌ 不发送短信/邮件（无此能力，口令由教师线下转达）。

**权限**：`TEACHER`

**路径参数**：`classId`（number，必填）

**请求体**

| 字段 | 类型 | 必填 | 约束 | 说明 |
| --- | --- | --- | --- | --- |
| studentNo | string | 是 | `^[A-Za-z0-9]{4,32}$`：字母数字，4–32 位，**不允许空格与中文** | 学号，同时作为登录名 |
| name | string | 是 | 去空格后 1–50 字符 | 学生姓名 |

```json
{ "studentNo": "2023010101", "name": "刘同学" }
```

**成功响应**

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "student": {
      "studentId": 10,
      "studentNo": "2023010101",
      "name": "刘同学",
      "username": "2023010101",
      "classId": 3,
      "className": "计算机2301班",
      "classStatus": 1,
      "status": 1,
      "createdAt": "2026-11-03 21:02:33"
    },
    "initialPassword": "K7mQ2xRt"
  }
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| student | object | 新建的学生对象，字段同 `StudentView` |
| initialPassword | string | **8 位初始口令明文，仅此一次**。字符集为大小写字母+数字，**已剔除易混淆字符 `0 O 1 l I`** |

**初始口令的硬约束（实现与答辩都要能讲）**

| 约束 | 说明 |
| --- | --- |
| 生成方式 | `SecureRandom`，8 位，字符集 `23456789ABCDEFGHJKLMNPQRSTUVWXYZabcdefghjkmnpqrstuvwxyz`（32 字符，去掉了 0O1lI） |
| 存储 | 只存 BCrypt 哈希进 `sys_user.password_hash`；**数据库中不存在明文列** |
| 回显 | 只在本接口成功响应里出现一次；**不存在"查看初始口令"接口** |
| 日志 | 任何日志、异常 message、审计记录都不得包含该值 |
| 丢失后 | 只能由教师走 S6 重置，旧口令立即失效 |
| 有效期 | **本模块不做强制改密**，口令长期有效。风险与取舍见 §11-Q5 |

**失败**

| code | 条件 | 备注 |
| --- | --- | --- |
| 4001 | `studentNo`/`name` 缺失或格式非法 | message 指明字段 |
| 2003 | 该学号已有学生档案 | 提示「学号 xxx 已被占用」 |
| 2007 | 该学号与某个 `sys_user.username` 冲突（学生或教师账号） | 与 2003 分开，便于前端定位 |
| 2006 | 目标班级已归档 | — |
| 2002 | 目标班级不存在 | — |

**事务与并发**

- `sys_user` 插入成功、`student` 插入失败 → **整体回滚**，不允许留下孤立账号。
- 并发添加同一学号：由 `uk_student_student_no` 与 `uk_sys_user_username` 兜底，捕获 `DuplicateKeyException` 后按索引名转 `2003` / `2007`。
- 同一班级并发添加不同学号：无冲突，不需要锁。

**响应体里的安全提醒（前端必须遵守）**

`initialPassword` 是**一次性敏感信息**。前端拿到后：

1. 用**模态弹窗**展示，弹窗**不可点击遮罩关闭**，必须点「我已抄录」才关；
2. 提供复制按钮；
3. 关闭后**不写入任何前端持久化存储**（不进 `localStorage`、不进 Pinia 持久化、不进 URL）；
4. 页面刷新后该值不可恢复，前端**不得**自行缓存以便"稍后再看"。

### S5 · PATCH `/api/students/{studentId}` —— 修改学生信息

**用途**：改姓名、改学号、转班、停用/恢复。

**职责边界**
- ✅ 可改：`name`（→ `sys_user.display_name`）、`studentNo`（→ `student.student_no`）、`classId`（转班）、`status`（停用/恢复）。
- ❌ **不可改** `username`（登录名终身不变）。
- ❌ **不可改** `role`、**不可改密码**（密码走 S6）。
- ❌ 不删除学生。
- ❌ 不允许把学生转入已归档班级（`2006`）。

**权限**：`TEACHER`

**路径参数**：`studentId`（number）

**请求体**（部分更新，只传要改的字段；一个都不传 → `4001`）

| 字段 | 类型 | 必填 | 约束 | 说明 |
| --- | --- | --- | --- | --- |

| studentNo | string | 否 | `^[A-Za-z0-9]{4,32}$` | 改学号，**不影响 `username`** |
| classId | number | 否 | 必须是 `status=1` 的班级 | 转班 |
| status | number | 否 | `0` 或 `1` | 停用/恢复 |

```json

```

**成功响应**：返回更新后的 `StudentView`。

**失败**

| code | 条件 |
| --- | --- |
| 4001 | 未提供任何字段；字段格式非法；试图修改 `username`/`password`/`role`（多余字段不报错但被忽略，见下） |
| 2004 | 学生不存在 |
| 2003 | 改后的学号与其他学生重复 |
| 2007 | 改后的学号与其他账号的登录名冲突 |
| 2006 | 目标班级已归档 |
| 2002 | 目标班级不存在 |

**多余字段的处理**：请求体里出现契约外的字段（如 `username`、`password`），**服务端忽略，不报错**。理由：报错会让前端调试变得脆弱，忽略则保证"改不动"——安全目标已达成。但**前端不得依赖这一点**去传多余字段。

**改学号的连锁影响（必须实现）**

| 影响面 | 行为 |
| --- | --- |
| `student.student_no` | 更新 |
| `sys_user.username` | **不变** |
| 学生登录 | 仍用**旧学号**（= `username`）登录 |
| 前端展示 | 详情页必须同时显示「学号」与「登录名」，并提示「登录名不随学号变更」 |

## 6. 状态流转与关键规则

### 6.1 班级状态机

```
        C2 新建
          │
          ▼
     ┌─────────┐   C4 归档（有未发布成绩则拒绝 2005）  ┌──────────┐
     │ status=1│ ─────────────────────────────────▶ │ status=0 │
     │  正常    │                                     │  已归档   │
     └─────────┘ ◀──── 不存在"恢复"接口（本期不做）──── └──────────┘
          │                                               │
          │ 可：改名、加学生、转班进入                        │ 可：查看名单、查看学生
          │                                               │ 不可：改名、加学生、转入、再归档
```

**本期不提供"恢复已归档班级"接口**。误归档的补救方式：新建同名班级（`uk` 含 `status`，允许）。这是有意的取舍，写入 §11-Q3。

### 6.2 学生状态机

```
S2 建号 → status=1 在读 ──S5 停用──▶ status=0 停用
                ▲                        │
                └────── S5 恢复 ─────────┘

无删除动作。停用的学生：不能登录（登录时按 1001 处理，复用主契约口径）、仍在名单里但默认不显示。
```

### 6.3 C4 归档时的校验顺序（**必须按此顺序，否则错误提示会误导**）

```
1. classId 存在？            否 → 2002
2. 该班 status=1？           否 → 2002（已归档不重复归档）
3. 是否存在未发布成绩？        是 → 2005    ← 模块四启用；模块二此步恒为"否"
4. 执行归档：
   a. 若已存在同 (name, grade_year) 的 status=0 记录 → 物理删除旧归档行（见 §3.2 说明）
   b. 置 status=0, archived_at=now()
5. 返回 affectedStudentCount（归档前的在读学生数）
```

**模块二的接入位**：第 3 步在模块二阶段直接短路为 `false`，但**必须在代码里留一个独立的校验方法**（如 `gradeGuard.hasDraftGrades(classId)`，模块二返回 `false`），这样模块四只需替换实现，不动 Controller 与错误码。

### 6.4 归档 vs 物理删除的边界（写给未来的自己）

| 场景 | 动作 |
| --- | --- |
| 班级名建错了 | C4 归档 → 需要的话 C2 重建 |
| 这届学生毕业了 | C4 归档 |
| 班级里还有个学生录错了班 | **不要归档班级**，用 S5 把他转到正确班级 |
| 想把某个学生从班里去掉（退课/退学） | **没有这个接口**。退学用 S5 停用；退课属于模块三的"移出课程"，不是"移出班级" |

> 这条要写进前端提示文案里：教师点"删除班级"时，弹窗说明「归档后班级不再出现在列表，学生与成绩数据保留」。

### 7.4 角色校验的前置改造（模块二的第一个提交）

现状：`WebMvcConfig` 只注册了 `SessionAuthInterceptor`（判"是否登录"），**没有角色校验**。

约定（两人都要按这个来，避免各写一套）：

1. 新增注解 `@RequireRole(role = "TEACHER")`，标在 Controller 类或方法上。
2. 新增 `RoleAuthInterceptor`，在 `preHandle` 里取 `HandlerMethod` 上的注解，比对 `SessionUser.role`，不符抛 `BusinessException(1003)`。
3. 注册顺序：`SessionAuthInterceptor` **必须在前**（先判登录，再判角色），否则未登录会得到 `1003` 而不是 `1002`。
4. 注册位置：`WebMvcConfig.addInterceptors` 内，**在已有 `registry.addInterceptor(...)` 之后追加一段**，不改动现有那段代码（降低合并冲突，见 §9）。
5. 拦截范围：`/api/**`，排除列表保持现状（`ping`/`login`/`logout`）。

### 9.3 Flyway 版本号预约（**最容易炸的一条**）

Flyway 对已执行过的脚本校验 checksum，**改动历史脚本会导致启动失败**（`Validate failed: checksum mismatch`）。

| 版本号 | 归属 | 内容 |
| --- | --- | --- |
| `V1` | ✅ 已执行 | `sys_user`（**禁止再改**） |
| `V2` | 模块二 | `school_class` |
| `V3` | 模块二 | `student` |
| `V4` 起 | 模块三及以后 | **不得占用 V2/V3** |

纪律：

1. 一个脚本只做一件事（一表一脚本），不要"V2 顺手加个索引"。
2. 脚本一旦在自己机器上执行过，**就当它已发布**，只能新增 V4 去改，不能回头改 V2。
3. 两人若在不同分支各写了 V2 → 合并后 Flyway 会按名称排序执行，可能顺序错乱。**必须是后端独占 V2/V3**，前端不产迁移脚本。
