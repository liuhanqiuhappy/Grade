## 0. 修改纪律（铁律）

1. **改接口先改本文件与 `openapi.json`**，两者同步更新后再改代码。禁止单边改字段。
2. 本契约确认生效后，任何一方不得在代码里出现契约之外的字段或路径。
3. 教师若下发官方契约（含 21 个接口的完整版），**以官方契约为准**，本文件降级为工作稿并对齐改写。

## 1. 通用约定

### 1.1 统一响应结构

所有接口（含业务失败）统一返回：

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| code | number | `0` = 成功；非 `0` = 业务失败（见错误码表） |
| message | string | 人类可读的提示，可直接展示给用户 |
| data | object / null | 业务数据；失败时为 `null` |

### 1.2 HTTP 状态码纪律

- **业务失败也返回 HTTP 200**，用 `code` 区分（如密码错误、未登录都是 200 + 对应错误码）。
- HTTP 非 200 仅保留给基础设施故障（服务未启动、网关错误等），正常业务代码不应产生。

### 1.3 认证方式

- **Session + Cookie**：登录成功后服务端创建会话，通过 `Set-Cookie: JSESSIONID=...` 下发，属性 `HttpOnly`。
- 后端**不放开 CORS**；开发期前端通过 Vite 代理把 `/api` 转发到 `http://localhost:8080`，浏览器视角同源，Cookie 自然携带。
- **身份由服务端从会话判定**，任何请求中的"我是教师/我是学生"这类客户端自述一律不采信（需求 §4.2 全局规则 1）。

### 1.4 基础地址

| 环境 | 地址 |
| --- | --- |
| 后端本机 | `http://localhost:8080` |
| 前端经代理 | `http://localhost:5173/api/...`（开发期推荐） |

探活接口：`GET /api/ping`。

## 2. 错误码表

| code | 含义 | 触发场景 | message 示例 |
| --- | --- | --- | --- |
| 0 | 成功 | — | ok |
| 1001 | 凭据错误 | 登录名或口令不匹配。**不区分"账号不存在"和"密码错误"**，统一提示，防止账号枚举 | 用户名或密码错误 |
| 1002 | 未登录或会话已过期 | 请求受保护接口但无有效会话 | 请先登录 / 登录已过期，请重新登录 |
| 1003 | 权限不足 | 已登录但以学生身份请求教师功能等越权场景 | 无权访问该功能 |
| 4001 | 参数校验失败 | 必填字段缺失或格式非法，message 指出缺失字段 | 用户名不能为空 |
| 5000 | 系统内部错误 | 服务端异常，前端提示"稍后重试"即可 | 系统繁忙，请稍后重试 |

## 3. 接口定义

> 完整机器可读定义见 `docs/openapi.json`，两处不一致时**以本文件为准并立即修正 json**。

### 3.1 GET /api/ping —— 探活

- 用途：前端/运维确认后端已启动，**不需要登录**。
- 响应：`code=0`，`data: { "status": "ok" }`。

### 3.2 POST /api/identity/login —— 登录（S01a）

- **不需要登录**。`Content-Type: application/json`。

**请求体：**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| username | string | 是 | 登录名 |
| password | string | 是 | 口令 |

> **请求体只有上面两个字段**，不接受 `remember` / `rememberMe` 之类的字段。「记住密码」是前端本地凭据缓存，不改变登录接口的入参与会话时长，约定见 **§3.8**。

**成功响应**（`code=0`），`data`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| userId | number | 用户 ID |
| username | string | 登录名 |
| displayName | string | 姓名（欢迎页展示用） |
| role | string | `"TEACHER"` 或 `"STUDENT"` |

**失败响应：**

| code | 条件 |
| --- | --- |
| 4001 | username 或 password 缺失/为空 |
| 1001 | 凭据不匹配 |

**对应验收**：正确凭据 → 返回身份；错误口令 → `1001`，前端不跳转。

### 3.3 GET /api/identity/me —— 查询当前身份（S01b / 会话恢复）

- **需要已登录会话**。
- 用途：前端页面刷新后恢复登录状态；判断会话是否仍有效。
- 成功：`data` 结构同 3.2 成功响应。
- 失败：`1002`（未登录/过期）→ 前端跳转登录页。

### 3.4 POST /api/identity/logout —— 退出（S01c）

- **需要已登录会话**；**设计为幂等**：即使会话已失效也返回 `code=0`，简化前端处理。
- 成功：`data: null`。服务端使会话失效。
- **对应验收**：退出后访问 `me` 等受保护接口返回 `1002`；换账号登录不串数据。

### 3.5 注册接口 —— **已移除（v0.4）**

原 `POST /api/identity/register` 及配套错误码 `1004`、注册页与 `RegisterRequest` 已随 v0.4 一并删除。账号一律由种子数据/管理员创建（开发期演示账号见 §3.7），不再提供自助注册。章节编号保留占位，避免后文 §3.6–§3.8 的引用失效。

### 3.6 输入格式约定（**已定稿**）

| 字段 | 规则 |
| --- | --- |
| username（登录） | 只校验非空 + 最长 32；**不校验格式**，避免格式错误被区分成 4001 而绕过 1001 的统一提示 |
| password（登录） | 只校验非空 + 最长 64 |

### 3.7 实现说明（不改变契约字段，仅记录口径）

- 口令存储：**BCrypt**（随机盐），库中 `sys_user.password_hash` 为 60 字符哈希，任何接口与日志都不出现明文。
- 会话：登录成功后**先销毁旧会话再新建**（防会话固定），`server.servlet.session.timeout=30m`。
- 账号停用与口令错误返回**同一个 1001**，且账号不存在时也执行一次哈希比对，避免通过响应时间或提示做账号枚举。
- 开发期演示账号（`app.demo-data.enabled=true` 时启动补齐）：`teacher01` / `student01`，口令均为 `pass1234`。

### 3.8 「记住密码」客户端约定（**纯前端，无接口**）

- **归属**：这是登录页的本地交互，**不新增接口、不新增请求字段、不改会话时长**。后端对「记住密码」完全无感知，登录校验流程与 §3.2 完全一致。
- **默认状态**：登录页复选框默认**不勾选**；不勾选时不写入任何凭据。
- **写入时机**：仅在「勾选 + 登录返回 `code=0`」同时成立时写入；登录失败（`1001`/`4001`/`5000`）**绝不写入**，避免把错密码记下来。
- **删除时机**：① 未勾选且登录成功 → 删除旧记录；② 记录结构不合法、版本不符或超过 30 天 → 读取时直接删除；③ 用户清除浏览器数据。
- **退出登录**：`logout` **不清除**记住的凭据——否则"简化后续登录"的目的落空；退出只销毁服务端会话。

**存储约定（前端实现口径）：**

| 项 | 取值 |
| --- | --- |
| 存储位置 | `localStorage`（不是 Cookie，不随请求自动发送） |
| 键名 | `gm.rememberedCredential` |
| 值 | `Base64(JSON)`：`{"v":1,"username":"...","password":"...","savedAt":<毫秒时间戳>}` |
| 有效期 | 30 天（由 `savedAt` 判断，过期即删） |
| 回填 | 登录页 `onMounted` 读取，回填账号与密码并把复选框置为勾选 |

**安全边界（必须在答辩时说明，别当成加密）：**

1. Base64 只是**编码**，不是加密，本机任何人打开 DevTools 都能还原明文密码。
2. 该密码**仍然要经过后端 BCrypt 校验**，不参与任何"跳过校验"的逻辑；后端不保存、不接收"记住密码"标记。
3. 课程/演示场景可接受；真实产品应改用**服务端签发的长效令牌（HttpOnly Cookie）**或一次性 token，而不是把口令留在浏览器。
4. 共用电脑为高风险场景，前端在勾选框旁给出"仅限个人设备"的提示文案。

**职责边界（并行开发时按这张表分工）：**

| 事项 | 归属 | 说明 |
| --- | --- | --- |
| 账号是否存在、口令是否正确 | 后端 | 只由 `POST /api/identity/login` 判定 |
| 会话建立/失效、30 分钟超时 | 后端 | `JSESSIONID` + `HttpOnly` |
| 记住/回填/清除凭据 | 前端 | 只碰 `localStorage`，不碰接口 |
| 错误提示文案 | 前端 | 直接用后端 `message`，不自行编造 |

## 5. 前端对接须知（给同伴）

1. 开发期在 `vite.config.js` 配置代理，**不要**用完整 `http://localhost:8080` 直连：

```js
server: {
  proxy: { '/api': 'http://localhost:8080' }
}
```

2. 登录请求后的所有请求**不需要手动带 Cookie**（代理同源，浏览器自动携带）。
3. 判断登录态：调 `GET /api/identity/me`，`code=0` 放行，`1002` 跳登录页。
4. 业务失败统一按 `code` 分支处理，**不要**用 HTTP 状态码判断业务结果。
5. 登录提交中显示等待状态并禁用按钮（防重复提交，需求验收明确要求）。
6. 记住密码（§3.8）：只操作 `localStorage['gm.rememberedCredential']`，**不要**在登录请求里加任何 `remember` 字段，也不要用它绕过登录校验。
7. 登录页必须处理 `4001`（展示后端 `message`，不跳转）与提交中按钮禁用。

## 6. 数据归属纪律

- 账号数据（登录名、口令、角色、姓名）**只存在于后端数据库**，前端不保存账号列表、不校验凭据。
- 口令存储方式：**BCrypt**（`sys_user.password_hash`，60 字符），明文不落库、不进日志、不回传。
- 例外且仅限一处：§3.8「记住密码」会在用户主动勾选后把凭据留在**本机 `localStorage`**，用于表单回填。它**不是**业务数据源——回填的密码仍要提交给 `login` 由后端判定，前端任何情况下都不得据此自行放行。
