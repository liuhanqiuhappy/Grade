### 本期定稿口径（契约 Q1–Q11 的落地取值）

| 事项 | 取值 |
| --- | --- |
| 会话 | Session + `JSESSIONID`，`HttpOnly`，`SameSite=Lax`，超时 30 分钟 |
| 认证方式 | 纯 Session Cookie；**不放开 CORS**，前端走 Vite 代理 |
| 口令存储 | BCrypt（60 字符哈希），明文不落库、不进日志、不回传 |
| 角色 | `TEACHER` / `STUDENT` 大写字符串；**只由服务端判定** |
| 注册 | **已移除（契约 v0.4）**：无自助注册，账号由种子数据/管理员创建 |
| 校验 | 登录用户名非空 + 最长 32；密码非空 + 最长 64（不校验格式，避免绕过 1001 统一提示） |
| 错误码 | `0/1001/1002/1003/4001/5000`；业务失败一律 HTTP 200 |
| 版本与路径 | 无 `/v1` 前缀，统一 `/api/**` |

## 2. 启动准备（后端本机）

1. 确认 MySQL 已启动（本机 3306）。
2. 设置数据库密码环境变量（**不要写进配置文件**）：

```powershell
$env:DB_PASSWORD = "你的MySQL密码"
# 可选覆盖：$env:DB_NAME / $env:DB_USERNAME / $env:DB_HOST / $env:DB_PORT
```

3. 启动（首次启动会自动建库 `grade_manager`、建表 `sys_user`、补齐演示账号）：

```powershell
cd d:/backend/backend
mvn spring-boot:run
```

4. 看到 `Started GradeManagerApplication` 后，浏览器访问 <http://localhost:8080/api/ping>，应返回：

```json
{ "code": 0, "message": "ok", "data": { "status": "ok" } }
```

**演示账号**（`app.demo-data.enabled=true` 时启动自动补齐，生产请关掉）：

| 登录名 | 口令 | 角色 | 姓名 |
| --- | --- | --- | --- |
| `teacher01` | `pass1234` | TEACHER | 周老师 |
| `student01` | `pass1234` | STUDENT | 刘同学 |

> 密码由服务端启动时现场 BCrypt 加密后入库，SQL 脚本里没有明文或写死的哈希。
> 若启动报 `Unsupported Database: MySQL 9.x`，见 §7 风险 1。

## 3. 逐条测试用例（前后端一起过）

约定：**所有响应 HTTP 都是 200**，只看响应体的 `code`。

| 编号 | 场景 | 操作 | 预期 `code` / `message` | 预期 `data` |
| --- | --- | --- | --- | --- |
| TC-01 | 探活 | `GET /api/ping` | `0 / ok` | `{"status":"ok"}` |
| TC-02 | 教师登录成功 | POST login，`teacher01` / `pass1234` | `0 / ok` | `userId`、`username=teacher01`、`displayName=周老师`、`role=TEACHER` |
| TC-03 | 学生登录成功 | POST login，`student01` / `pass1234` | `0 / ok` | `role=STUDENT` |
| TC-04 | 漏填密码 | POST login，body 只有 `username` | `4001 / 密码不能为空` | `null`，**不跳转** |
| TC-05 | 用户名为空串 | POST login，`"username":""` | `4001 / 用户名不能为空` | `null` |
| TC-06 | 口令错误 | POST login，正确账号 + 错口令 | `1001 / 用户名或密码错误` | `null` |
| TC-07 | 账号不存在 | POST login，`nobody` / 任意口令 | `1001 / 用户名或密码错误`（**与 TC-06 完全一致**） | `null` |
| TC-08 | 未登录查询身份 | 清 Cookie 后 `GET /api/identity/me` | `1002 / 登录已过期，请重新登录` | `null` |
| TC-09 | 会话恢复 | 登录成功后 `GET /api/identity/me` | `0 / ok` | 与登录返回一致 |
| TC-10 | 退出 + 幂等 | `POST /api/identity/logout` → `GET me` → 再 `POST logout` | `0 / ok` → `1002` → `0 / ok` | `null` |
| TC-11 | 换账号不串数据 | `teacher01` 登录 → 退出 → `student01` 登录 → `GET me` | `0`，返回 `student01` / 刘同学 / STUDENT | 不得残留教师信息 |
| TC-12 | 请求体非法 JSON | POST login，body `{"username": ` | `4001 / 请求参数格式不正确` | `null` |

### 前端用例（浏览器手动过，配合上面接口用例）

| 编号 | 场景 | 操作 | 预期 |
| --- | --- | --- | --- |
| TC-F1 | 记住密码生效 | 勾选「记住密码」→ 登录成功 → 退出 → 刷新登录页 | 账号密码已回填、复选框已勾选；`localStorage['gm.rememberedCredential']` 存在 |
| TC-F2 | 取消记住密码 | 取消勾选 → 登录成功 → 退出 | `localStorage['gm.rememberedCredential']` 被删除，刷新后表单为空 |
| TC-F3 | 登录失败不写凭据 | 勾选状态下输错密码登录 | 提示「用户名或密码错误」，本地记录**不被覆盖/写入** |

### 数据核对（DBeaver）

```sql
SELECT id, username, display_name, role, status,
       LEFT(password_hash, 4) AS hash_prefix, CHAR_LENGTH(password_hash) AS hash_len
FROM sys_user
ORDER BY id;
```

预期：
- `hash_prefix = $2a$` 且 `hash_len = 60` → 确实是 BCrypt 哈希；
- 任意一行都**看不到** `pass1234` 这样的明文；
- `username` 有唯一索引，重复插入会被数据库拒绝。

## 4. 一键冒烟（PowerShell，逐条打印 code）

后端直连（不依赖前端）：

```powershell
$api = "http://localhost:8080/api"
$s = New-Object Microsoft.PowerShell.Commands.WebRequestSession

"--- ping ---"
Invoke-RestMethod "$api/ping" | ConvertTo-Json -Depth 5

"--- 登录成功 ---"
Invoke-RestMethod "$api/identity/login" -Method Post -ContentType "application/json" `
  -Body '{"username":"teacher01","password":"pass1234"}' -WebSession $s | ConvertTo-Json -Depth 5

"--- me（带会话）---"
Invoke-RestMethod "$api/identity/me" -WebSession $s | ConvertTo-Json -Depth 5

"--- 口令错误 ---"
Invoke-RestMethod "$api/identity/login" -Method Post -ContentType "application/json" `
  -Body '{"username":"teacher01","password":"wrong"}' -WebSession $s | ConvertTo-Json -Depth 5

"--- 漏填密码 ---"
Invoke-RestMethod "$api/identity/login" -Method Post -ContentType "application/json" `
  -Body '{"username":"teacher01"}' -WebSession $s | ConvertTo-Json -Depth 5

"--- 退出 ---"
Invoke-RestMethod "$api/identity/logout" -Method Post -WebSession $s | ConvertTo-Json -Depth 5

"--- 退出后 me ---"
Invoke-RestMethod "$api/identity/me" -WebSession $s | ConvertTo-Json -Depth 5
```

经前端代理联调时，把 `$api` 改成 `http://localhost:5173/api`：Cookie 由浏览器/会话自动携带，**前端不要手写 JSESSIONID**。

> 注意：PowerShell 5.1 里 `curl` 是 `Invoke-WebRequest` 的别名，别照抄 Linux 的 curl 参数。

## 5. Apifox 联调步骤

1. 导入 `docs/openapi.json`（或让前端从仓库拉最新版），环境变量 `baseUrl = http://localhost:8080`。
2. 先跑 `GET /api/ping` 确认环境通。
3. 跑 `POST /api/identity/login`（用演示账号），在 Apifox「Cookie 管理」里确认已自动保存 `JSESSIONID`；随后的 `GET /api/identity/me`、`POST /api/identity/logout` 会自动带 Cookie。
4. 断言写 `$.code`，**不要**写 HTTP 状态码断言（业务失败也是 200）。
5. 用「目录 → 运行」把 §3 的 TC-01～TC-12 存成测试用例集，截图留档（课程要求每条验收可复现）。

## 6. 用户故事验收对照

| 验收项（实验一） | 对应用例 | 判定 |
| --- | --- | --- |
| 打开网页显示登录表单 | 前端页面 | 前端 |
| 漏填用户名或密码 → 指出缺失字段、不跳转 | TC-04 / TC-05 | 后端返回 4001 + 具体字段名 |
| 提交中显示等待状态、防重复提交 | 前端按钮禁用 | 前端 |
| 账号或密码不匹配 → 显示失败、不进入欢迎页 | TC-06 / TC-07 | 后端统一 1001 |
| 登录成功 → 进入欢迎页、显示用户名 | TC-02 / TC-03 / TC-09 | 后端返回 `displayName` |
| 退出 → 返回登录页；退出后访问受保护页被拦 | TC-10 | 退出后 `me` 返回 1002 |
| 换账号登录不串数据 | TC-11 | 会话重置，无残留身份 |
| 账号数据只在后端 | DBeaver 核对 | 库中只有哈希 |

## 7. 已知限制与风险

1. **本机 MySQL 版本为 9.7.1**，课程标准是 8.4。若启动报 `Unsupported Database: MySQL 9.7`：
   - 方案 A（推荐）：装/连一个 MySQL 8.4 实例，用 `DB_PORT` 指过去；
   - 方案 B：在 `backend/pom.xml` 的 `<properties>` 里加 `<flyway.version>10.20.1</flyway.version>`，让 Flyway 支持 9.x。
2. **会话存在应用内存**：重启后端即全部失效（前端会收到 1002 并跳登录页，属预期行为）；不支持多实例部署。
3. **未实现登录限流**：连续暴力尝试不会被阻断。课堂作业范围外，若要做需先在契约里加错误码（如 1005）。
4. **注册功能已移除（契约 v0.4）**：`/api/identity/register` 返回 404（NoResourceFoundException 走 Spring 默认处理），属预期行为。
5. **控制台中文日志在 PowerShell 显示为乱码**（GBK 控制台），不影响接口与数据；可先 `chcp 65001`。
