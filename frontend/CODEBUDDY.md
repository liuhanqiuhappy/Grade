### 「记住密码」实现口径（契约 §3.8）

| 项 | 约定 |
| --- | --- |
| 存储 | `localStorage['gm.rememberedCredential']`，值为 `Base64(JSON)`，含 `v/username/password/savedAt` |
| 写入 | **仅「勾选 + 登录成功」**；登录失败绝不写入 |
| 回填 | 登录页 `onMounted` 读取并回填，自动勾选 |
| 清除 | 未勾选且登录成功、记录损坏/超 30 天、用户清浏览器数据；**退出登录不清除** |
| 边界 | 不改登录接口字段、不改会话时长；密码仍需后端校验；Base64 不是加密，仅演示可接受 |

## 请求与状态纪律

1. **前端不产生业务数据**：不保存账号列表、不校验凭据正确性，一切以后端返回为准。
2. 所有请求走 `/api/**`，axios 基础路径设为 `/api`；**不要手动携带 Cookie**（代理同源自动携带）。
3. 业务结果按响应体的 `code` 分支处理（`0`=成功，`1001`/`1002`/`4001`…见契约错误码表），**禁止用 HTTP 状态码判断业务结果**（业务失败也是 HTTP 200）。
4. 登录态判断：调 `GET /api/identity/me`，`code=0` 放行，`1002` 跳登录页。路由守卫统一做。
5. 任何字段、路径以契约为准；发现契约缺东西 → 先提出来改契约，**不许代码里私加字段**。
6. 错误提示：登录/注册请求带 `silent: true`，由页面内联展示后端 `message`，不重复弹 alert。
7. 表单校验只用于**提前提示**，不得替代后端判定；`confirmPassword` 只在前端存在。

## 验收自查（提交前逐条过）

- [ ] 未登录打开系统 → 显示登录表单
- [ ] 漏填用户名或密码提交 → 指出缺失字段，不跳转
- [ ] 提交中 → 显示等待状态，按钮禁用（防重复提交）
- [ ] 密码错误（后端 `1001`）→ 显示失败提示，不进入欢迎页
- [ ] 登录成功 → 进入欢迎页，显示用户名
- [ ] 退出 → 返回登录页；浏览器后退/直接输地址进受保护页 → 被守卫拦回登录页
- [ ] 换账号登录 → 只显示新账号的数据
- [ ] 注册：合法信息提交 → 跳登录页并回填账号，未自动登录
- [ ] 注册：两次密码不一致 → 前端提示，不发请求
- [ ] 注册：重复账号 → `1004` 提示「用户名已被注册」，停在注册页
- [ ] 记住密码：勾选并登录成功 → 刷新登录页后账号密码已回填、复选框已勾选
- [ ] 记住密码：取消勾选再登录 → 本地记录被清除，刷新后表单为空
- [ ] 记住密码：密码错误 → 不写入本地记录
